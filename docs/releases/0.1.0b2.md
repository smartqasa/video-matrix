# Video Matrix 0.1.0b2

Fix source selection errors on No Hassle NHAV-8X16V5 devices that return a stale
`video switch` acknowledgement to status requests while a route settles.

- Retry status confirmation up to three times, including protocol and connection
  errors. Each request retains its five-second timeout, with half a second between
  attempts. Only a valid snapshot with the requested route confirms success.
- Send each switching command once. A timed-out or failed write remains an error,
  even when later status reads succeed; failed reconciliation preserves both errors.
- Avoid making all outputs unavailable for a transient read that recovers within
  the confirmation budget. Exhausted failed reads still mark outputs unavailable.
- Include a bounded response-shape diagnostic without logging private device labels
  or arbitrary response values.

Validation: 72 automated tests, including the real HTTP driver receiving two stale
acknowledgements before valid status, plus failure, cancellation, and serialization
regressions. The stale-acknowledgement sequence was reproduced on live hardware;
the test route was restored and verified. Physical picture confirmation remains
pending.

Update through HACS with Video Matrix's **Pre-release** switch enabled, then
restart Home Assistant. Entity IDs and existing source-name overrides are retained.
