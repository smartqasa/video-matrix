# Video Matrix 0.1.0b3

Fix an unload race that allowed a queued source-selection action to switch a
matrix after Home Assistant had finished unloading the integration.

- Reject queued or stale commands during unload, including commands held by an
  old coordinator after the integration is loaded again.
- Let an active transaction settle and wait for driver cleanup before completing
  unload. An already-sent switching command cannot be undone.
- Preserve Home Assistant's shared HTTP session. Cancellation of a cleanup waiter
  does not abandon cleanup; failed driver cleanup can be retried.
- Add permanent tests for overlapping actions and unload, cancellation, repeated
  setup, and automatic recovery through scheduled polls and initial-setup retries.

Polling and initial-setup retry timing are unchanged. Power-loss and offline-startup
checks on the previous beta recovered automatically; this release does not claim
to fix a permanent reconnection failure.

Validation: 84 automated tests pass with 99% coverage, including the real HTTP
driver against simulated matrix devices. Lint and formatting checks pass. The new
unload behavior has not been exercised on physical hardware; physical picture
confirmation remains pending.

Update through HACS with Video Matrix's **Pre-release** switch enabled, select
**0.1.0b3**, then restart Home Assistant. If the release is not listed yet, use
HACS's **Update information** action for this repository. Entity IDs and existing
source-name overrides are retained.
